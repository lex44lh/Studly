# STUDLY — инструкции для Frontend

## Область применения
Эти правила относятся к задачам Frontend (`apps/web`) и документации Frontend. Backend разрабатывает другой сотрудник на Django REST Framework и PostgreSQL. Не менять `apps/api`, Django, БД, миграции, серверную авторизацию или Backend-ветку. Не создавать API Next.js взамен Django. Инструкции Backend-разработчика сохраняются в его области; этот файл не разрешает работу над Backend.

Сначала изучать существующий код и вложенные AGENTS.md. Сохранять незакоммиченные изменения и утверждённый дизайн. Не делать commit, push или merge без отдельного разрешения. Не применять force push. Не добавлять архив studly-logo-files.zip в коммиты.

## Постоянная отчётность Frontend
После каждого завершённого действия или логического этапа обновлять тематический Markdown-отчёт внутри `/Users/alekspih/Documents/Projects/для отчетов/`; не откладывать записи до конца задачи. Для каждого нового сеанса и темы создавать отдельный `YYYY-MM-DD_HH-mm_<topic>.md` и обновлять индекс `/Users/alekspih/Documents/Projects/для отчетов/README.md`. Тематические папки создавать только по необходимости (`frontend/registration`, `frontend/catalog`, `frontend/profile`, `frontend/api-integration`, `git` и другие).

Отчёт содержит заголовок STUDLY, дату, фактическое начало/окончание и часовой пояс Europe/Moscow; цель; выполненные действия с началом/окончанием, файлами и результатами; созданные/изменённые/удалённые файлы; проверки TypeScript, ESLint, build и прочие; проблемы, ограничения, следующие действия; ветку, commit, наличие незакоммиченных изменений и факт push. Получать время из системных часов с переводом в Europe/Moscow; не выдумывать отметки. Для незапущенных проверок писать «Не запускалась». Ошибки и неудачные попытки фиксировать с причиной (если известна), исправлением и остаточным состоянием.

Не записывать пароли, ключи, токены, Telegram initData, секреты окружения и приватные пользовательские данные. Основной каталог отчётов по последнему указанию пользователя находится вне репозитория: `/Users/alekspih/Documents/Projects/для отчетов` (Документы/Projects/для отчетов). Новые отчёты сохранять только там; инструкции AGENTS.md остаются в репозитории. Старые копии в documents/project/для отчетов сохранены как история, но больше не являются основным каталогом. Внешние отчёты автоматически не включаются в Git; не копировать их обратно ради коммита без указания пользователя. Эти правила распространяются на последующие задачи Frontend и связанную с ними работу с Git; не вводят обязательств и изменений для Backend-разработчика.
