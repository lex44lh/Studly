# STUDLY — инструкции для Frontend

## Область применения
Эти правила относятся к задачам Frontend (`apps/web`) и документации Frontend. Backend разрабатывает другой сотрудник на Django REST Framework и PostgreSQL. Не менять `apps/api`, Django, БД, миграции, серверную авторизацию или Backend-ветку. Не создавать API Next.js взамен Django. Инструкции Backend-разработчика сохраняются в его области; этот файл не разрешает работу над Backend.

Сначала изучать существующий код и вложенные AGENTS.md. Сохранять незакоммиченные изменения и утверждённый дизайн. Не делать commit, push или merge без отдельного разрешения. Не применять force push. Не добавлять архив studly-logo-files.zip в коммиты.

## Постоянная отчётность Frontend

По указанию пользователя от 16 октября 2026 года отчёты хранятся в `documents/project/для отчетов/` и публикуются вместе с соответствующим Frontend-кодом. После каждого логического этапа обновлять тематический `YYYY-MM-DD_HH-mm_<topic>.md` и индекс README.md. Темы: frontend/api-integration, frontend/registration, frontend/catalog, git.

Отчёт содержит фактическое начало/окончание Europe/Moscow, цель, действия, файлы, endpoints, ссылку на Backend-контракт и его commit hash, проверки, ошибки, ограничения, следующие действия и Git-статус. Время получать из системных часов; для незапущенных проверок писать «Не запускалась». Не записывать секреты, initData и персональные данные. Не публиковать локальные материалы сотрудника и архив логотипов. Старые внешние отчёты не переносить автоматически.
