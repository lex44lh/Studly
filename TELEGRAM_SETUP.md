# STUDLY: состояние настройки Telegram

Состояние подключения проверено 15 октября 2026 года. Уточнение приоритета 16 октября: владелец выбрал первую версию через отдельный сайт с Telegram-входом и рублёвой оплатой. Настройки Telegram на этом шаге не менялись. Для настоящего входа с сайта остаются нужны зарегистрированный адрес возврата, отдельный Client Secret и подключение интерфейса его разработчиком. Порядок ниже описывает эти оставшиеся действия.

## Что настроено

Владелец проекта создал бота [@studly_service_bot](https://t.me/studly_service_bot), имя — STUDLY, Telegram Bot ID — `8817888875`. При проверке официальный метод `getMe` подтвердил эти данные.

Токен записан в локальный `apps/api/.env`, исключённый из Git. Доступ к файлу ограничен владельцем. Из подтверждённого Bot ID заполнен `TELEGRAM_OIDC_CLIENT_ID`; отдельный Client Secret не подменялся токеном бота.

Через Telegram API установлены и прочитаны обратно описание и краткое описание: «STUDLY — платформа образовательных услуг». Существующее имя бота сохранено. Отправка сообщений пользователям не выполнялась.

Backend перезапущен. Проверка настоящими HTTP-запросами к локальному серверу подтвердила:

- `health` отвечает `200`;
- обработчик Mini App загрузил токен и отклоняет поддельные данные с `401 invalid_telegram_data`;
- вход на сайте отвечает `503 telegram_not_configured`, пока отсутствуют Client Secret и адрес возврата.

Это проверка подключения бота и конфигурации сервера, а не успешный вход настоящего пользователя через Telegram. Проверки подписи и сессий ранее прошли в 33 автоматических тестах с вымышленными данными.

## Что требуется дальше

Сейчас проект работает только на компьютере, публичного HTTPS-адреса нет. Telegram подтвердил, что Main Mini App пока не включён; текущее меню бота имеет тип `commands`.

Владелец выбрал постоянное размещение и подтвердил, что сервера и домена пока нет. Порядок получения HTTPS и границы настройки по токену описаны в [DEPLOYMENT.md](DEPLOYMENT.md). В этом этапе публичное размещение и изменение кнопки бота не выполнялись.

Для открытия приложения из Telegram нужен HTTPS-адрес его интерфейса. После появления этого адреса кнопку меню можно настроить через официальный метод `setChatMenuButton`. Доступный только на компьютере адрес `127.0.0.1` не является публичным адресом приложения. Прежняя локальная интеграция интерфейса убрана после уточнения владельцем разделения работы; актуальный Frontend друга (`origin/main`, `ccfde59`) пока не подключён к API. Подключение выполняет разработчик Frontend. Публичного размещения ещё нет. OIDC callback пока отвечает JSON; при настройке настоящего входа нужно завершить переход обратно в профиль интерфейса.

Для входа на сайте владельцу бота нужно открыть настройки бота в BotFather → Login Widget, зарегистрировать адрес приложения и точный callback, получить Client Secret. Этот шаг требует доступа владельца к BotFather; доступная нам авторизация токеном в Bot API не является сеансом владельца.

После определения общего публичного адреса приложения callback имеет путь:

```text
<публичный HTTPS-адрес>/api/v1/auth/telegram/callback/
```

Этот путь предполагает, что `/api/` на выбранном публичном адресе направляется в Django. В актуальном Frontend друга прокси пока отсутствует; маршрутизацию нужно согласовать с его разработчиком. Публичное размещение ещё не настроено.

В локальном `apps/api/.env` затем заполняются:

```dotenv
TELEGRAM_OIDC_CLIENT_SECRET=
TELEGRAM_OIDC_REDIRECT_URI=
```

Значение Client ID нужно сверить с BotFather; в текущей конфигурации используется подтверждённый Bot ID. Для OIDC сохраняется алгоритм `RS256`. После заполнения параметров Backend перезапускается и проверяется вход с настоящим аккаунтом из Mini App и с сайта.

## Обновление токена

Текущий токен был передан в чат. Рекомендуется перевыпустить его в BotFather и вставить новый непосредственно в локальный `apps/api/.env`, в поле `TELEGRAM_BOT_TOKEN`, затем перезапустить Backend. Новый токен не следует отправлять в чат. Для OIDC Client Secret используется отдельное поле; его также вводят локально.
