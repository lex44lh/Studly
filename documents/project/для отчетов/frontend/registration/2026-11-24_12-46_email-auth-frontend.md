# STUDLY — клиентские формы email-входа и регистрации

24.11.2026, 12:46–13:01 МСК. Ветка `codex/frontend-email-auth-2026-11-24`, база `2b7c973694e08f07389641c77726b5b987cd968c`. Цель — подключить формы к опубликованному Django API для совместной проверки на изолированном стенде.

## Что реализовано

- Вход по почте или логину, запрос письма для регистрации, выбор логина и пароля после подтверждения, запрос восстановления и смена пароля. Формы используют компоненты и стили регистрации Campus. Разница между отключённым способом, ошибкой, загрузкой и нейтральным подтверждением запроса письма отображается в интерфейсе.
- `GET /api/v1/auth/options/` управляет доступом вместе с флагом сборки `NEXT_PUBLIC_STUDLY_EMAIL_AUTH_UI=1`. В Demo маршрут недоступен. Тестовый вход находится по `/auth/email`. Роуты выбора ролей и профиля открываются в тестовой конфигурации только при подтверждённой сессии и флаге регистрации сервера. Существующий Telegram-поток не заменён. Привязка почты к Telegram-аккаунту остаётся отдельным сценарием и на стенде выключена.
- Перед `POST /api/v1/auth/email/{register,verify,login,reset/request,reset/confirm}/` получается CSRF. После входа или подтверждения проверяются новый CSRF, `/auth/me/` и `/api/v1/registration/`. Успешная запись без подтверждающего чтения не повторяется автоматически. При открытии ссылки из письма фрагмент удаляется через `history.replaceState`; одноразовое значение остаётся в памяти формы. Пароли и токены не сохраняются в хранилище.
- Существующий чат «Интеграция Frontend с Backend» независимо сопоставил контракт с исходной версией и выделил требования к CSRF и продолжению регистрации. Оркестратор внёс изменения и проверил сборку.

## Передача Виктору

На тестовом HTTPS-стенде собрать указанный SHA Frontend с `NEXT_PUBLIC_STUDLY_EMAIL_AUTH_UI=1`, указать `STUDLY_EMAIL_ACTION_URL=https://live-test.studly-help.ru/auth/email` и подтвердить маршрут, конфигурацию доставки в закрытую тестовую почту и версии процессов. Для полного браузерного E2E нужны письмо регистрации, вход по двум идентификаторам, сброс с проверкой отзыва старых сессий, продолжение профиля и отдельные заказчик и исполнитель. На рабочем сайте email пока не включать. Публикация в GitHub охватывает только файлы клиента, тесты, отчёт и индекс.
