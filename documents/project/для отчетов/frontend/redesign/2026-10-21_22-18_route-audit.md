### Общие оболочки, состояния и отсутствующие маршруты

- `app/layout.tsx`: AuthProvider → AppShell. AppShell даёт FavoritesProvider; на момент аудита CampusShell используется только в search/service, остальные страницы имеют Sidebar/BottomNav с inline-цветами.
- `CampusShell` на момент аудита считает активным только «Поиск». Для всего приложения нужен корректный active section и действительный skip target; изменение общей оболочки выполняет основной агент этой задачи.
- **Live guard:** AppShell блокирует `/orders/**`, `/chats/**`, `/create-service`, `/notifications` через явное уведомление и disabled fieldset. Сохранение этой границы обязательно.
- **Registration production gate:** `register/layout.tsx` монтирует RegistrationProvider только в development. В production остаётся «Регистрация скоро появится» и ссылка в каталог. Этот gate нельзя снимать при редизайне.
- Отдельных `/register`, `/settings`, редактирования/управления услугами в текущем App Router нет. Их не создают ради списка желаемых интерфейсов.
- На момент аудита отсутствовали `loading.tsx`, `error.tsx`, `not-found.tsx`, `global-error.tsx`, middleware, route handlers и route groups. Loading/error/empty уже существуют внутри страниц, ApiState и RegistrationStep.
- ServiceCard требует визуального выравнивания с Campus и доступного имени favorite-кнопки; функциональная основа FavoritesContext сохраняется.
- Live DTO публичной услуги не содержит категории/рейтинга/фото; профиль исполнителя имеет только id/name/about. Нельзя имитировать отсутствующие поля.
- Legacy CSS сочетает тёмный body с жёстко белыми карточками; общий переход на токены должен охватить формы, состояния и страницы.

1. `/about`: Campus hero, утверждённый брендовый текст, исходное описание платформы, ссылка в каталог и навигация существующих справочных разделов.
