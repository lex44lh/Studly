## 1. F1 / P2: имя и собственное сохранение аватара

Причина: dirty text form запоминала global revision R. Отдельная собственная загрузка/удаление аватара успешно создавала R+1, но форма продолжала отправлять expectedRevision=R. Правильный CAS repository отклонял обычную пользовательскую последовательность как внешнюю гонку.

Исправление:

1. `ProfileEditor.updateAvatar` отправляет **тот же просмотренный base revision** в `saveAvatar(file,{expectedRevision})`.
2. Provider возвращает **точную committed revision** после завершения настоящей transaction.
3. Форма продвигает свой base к этому значению только после успеха и только если её прежний base всё ещё совпадает с captured revision. Нет безусловного принятия latest revision и нет отключения CAS.
4. Внешняя запись до аватара отклоняет stale avatar action; после аватара — stale text action. Несохранённый ввод остаётся в форме, пока пользователь явно не загрузит актуальные данные.

Actual ProfileEditor/domain/CAS tests: **6/6 PASS**. До fix **5 FAIL/1 PASS**. Red повторён root на восстановленных в памяти исходных bytes AccountWorkspace, SHA совпал с frozen manifest; product source не откатывался. [Red log](implementation/2026-10-23-f123/f1-red.log). Покрыты upload+text+reload, remove+text+reload, внешняя запись до/во время/после avatar action, ошибка сохранения и сохранённый ввод.

**Браузер PASS:** изменено имя→выбран локальный PNG→сохранено имя→reload (оба изменения на месте). Повторено имя→явное удаление аватара→save→reload (имя сохранено, reference очищена, Blob-файлы не удалены). Затем собственный avatar commit→реальная внешняя name write во второй вкладке→stale save: показан conflict, canonical имя осталось из B, input A сохранён.

## 2. F2 / P2: retry и независимость metadata от preview

Причина: retry восстанавливал avatarId без полного loading lifecycle. Пустая до чтения Blob строка avatarUrl трактовалась Provider как удаление reference. Preview URL и сохранённая identity файла были ошибочно связаны.

Исправление:

- `saveRegistration` по умолчанию **сохраняет canonical reference**. Пустой preview не удаляет аватар. Удаление возможно только с явным avatarIntent=`remove` из пользовательского действия формы; новый File сохраняется как отдельный replacement. Wire DTO не менялись.
- Retry синхронно выставляет loading/ref guards до чтения, даже при прежнем avatarId, и начинает новую попытку getAsset. Во время ожидания реальная форма скрыта; autosave/saveStep закрыты также внутренними refs.
- Failed/missing getAsset даёт понятный error, не снимает reference и не запускает зависимое сохранение. Доступны повтор чтения, повторный выбор файла либо явное удаление. После failure локальные текстовые правки не теряются. В error block есть отдельная кнопка «Удалить недоступный аватар»: её реальный onClick проверен компонентным regression test, включая сохранение текста. Финальная read-only сверка выявила отсутствие этой кнопки; дополнительный red/green сохранён в evidence.
- Generation guards отменяют устаревшие callbacks/queued intents; поздний asset не заменяет новый выбор/удаление. SaveStep повторно проверяет generation и avatar guards после await очереди.
- Retry отделён от прежней rejected Promise chain: Next работает после восстановления **без обязательного нового редактирования**.
- Чистая вкладка при входящем text update с тем же avatarId сохраняет уже готовое preview, а не стирает его.

Actual adapter tests: **17/17 PASS** (11 прежних +6 F2); actual Provider callbacks: **4/4 PASS**. Покрыты cross-tab conflict, retry, delayed/failed getAsset, программный edit и Next до resolve, same-ID retry, explicit remove после failed read, ready preview при clean external update, Next без нового ввода, reload/reference preservation. Provider тест отдельно проверяет actual emitted avatarId и exact avatar revision; persistence boundary в нём controlled, не native IDB.
