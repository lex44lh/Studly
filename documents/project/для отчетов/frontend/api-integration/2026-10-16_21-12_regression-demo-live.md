## Конкретное требование к Backend/инфраструктуре
Запустить существующий Django checkout codex/backend с его PostgreSQL, окружением и миграциями по инструкции сотрудника. В каталоге Backend apps/api документирован запуск `.venv/bin/python manage.py runserver 127.0.0.1:8000`. В Frontend-ветке не заменять Backend и не делать merge ради запуска. Проверить ready/services напрямую, затем через общий origin Frontend. Для services ожидается 200; me без входа может штатно вернуть 403, а не транспортный 500. Если Django работает по другому адресу, задать серверный DJANGO_API_ORIGIN и перезапустить Frontend. Согласовать Host/CSRF trusted origins и Telegram HTTPS; не смешивать localhost и 127.0.0.1 в одной сессии.
RUN_LOCAL.md Backend исторически сообщает «сервер уже запущен», но фактическая проверка этого сеанса опровергает доступность на настроенном адресе. Почему тот процесс был остановлен/не запущен, по текущему состоянию установить нельзя. Это не исправляется выдуманными данными или изменением CORS.
Категории, рейтинги, чаты, уведомления ещё не имеют необходимых API. Orders API в Backend есть, но клиентский сценарий пока не подключён. OIDC callback пока JSON; реальная регистрация в production остаётся закрытой до совместного прогона.
