## Безопасность

- **Высокий приоритет.** Оба работающих релиза используют Next.js 16.3.4 и sharp 0.35.4 на Linux с glibc. Они попадают в диапазон критического предупреждения Vercel об обработке изображений. Эксплуатация и факт инцидента не подтверждены. npm audit дополнительно отметил source-map-js. Целевая версия, предложенная аудитом для Next.js, — 16.4.6. После сборки проверить фактическую версию sharp не ниже 0.35.5 и повторить аудит. [Предупреждение Vercel](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw) · [Next.js 16.4.6](https://github.com/vercel/next.js/releases/tag/v16.4.6).
- **Средний приоритет.** На HTML-ответах `/`, `/profile`, `/staff`, `/auth/email` отсутствуют HSTS, CSP и X-Frame-Options. На проверенных Django-ответах есть HSTS на 3600 секунд и X-Frame-Options DENY. При добавлении политики встраивания проверить Telegram Mini App.
- На обоих доменах в окружениях активных Gunicorn установлены Django 5.2.18 и DRF 3.18.3. HTTP редиректит на HTTPS. Проверки цепочки TLS успешны, сроки действия предъявляемых сертификатов — 15.01.2027 и 19.02.2027 соответственно. Next.js, PostgreSQL и проверенные порты Prometheus слушают локальные адреса. На `GET /api/v1/auth/csrf/` cookie с HttpOnly, Secure, SameSite=Lax. Такие же флаги у сессионной cookie после штатного входа на стенде.
- Гостевые `/api/v1/auth/me/`, `/api/v1/account/`, `/api/v1/staff/me/` дали 403 на обоих доменах. Рабочий `/admin/` перенаправляет гостя на вход Django, стенд возвращает 404. Обычный тестовый заказчик после входа получает 200 на `auth/me/` и `account/`, 403 на `staff/me/`. Тестовый исполнитель штатно вышел, сервер вернул 204, сессионная cookie удалена и `auth/me/` вернул 403.

## Баги и сценарии

- Рабочий `/api/v2/services/` вернул 0 опубликованных услуг, `/search` корректно показал пустой каталог. Карточка открылась из каталога HTTPS-стенда, где опубликованы две тестовые услуги. На рабочей `/about` по-прежнему отсутствуют ссылки Telegram и TikTok.
- В Chromium 1440 и 390 px прошли сохранение тёмной темы после перезагрузки, нормализация ведущего нуля в цене, ошибка при «От 1000 / До 999», применение мобильного фильтра по кнопке и экран входа на закрытых страницах. На стенде проверены обычный email-вход двумя существующими тестовыми аккаунтами и переключение «Ссылка → Файл → Ссылка». Браузер переиспользовал один DOM-элемент, но сохранил введённый URL и очистил выбранный файл. Первый запуск ожидал карточку в пустом рабочем каталоге и проверял форму до загрузки auth options. Повторный запуск учёл оба условия. Стороннее подключение Telegram в браузерной проверке изолировано.
- **Риск целостности переписки.** В обоих SHA Backend обычная отправка берёт блокировку строки беседы, а выпуск удержанного сообщения из модерации присваивает новый sequence под другой блокировкой. При конкуренции курсор может продвинуться раньше видимости сообщения с меньшим sequence. Это вывод по коду, сбой на работающем стенде не подтверждён. Передать Backend для единообразного выделения sequence и отдельной проверки конкуренции в PostgreSQL.

Запущены 400 локальных тестов Frontend, TypeScript, ESLint и `git diff --check`. ESLint выдал два прежних предупреждения об `<img>` в форме создания услуги. Обычные HTTPS-запросы с Mac и через VPS вернули 200. Браузерный прогон выполнен через диагностический SSH-туннель. Совместный Live-заказ, переписка, реальный Telegram-вход, приёмка прав модератора, загрузка портфолио на сервер, восстановление резервных копий — **Не запускалась** проверка.
