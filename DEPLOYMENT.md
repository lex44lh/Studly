## Что означает HTTPS

`http://127.0.0.1:3000` — адрес на текущем компьютере. Он не открывает ваш компьютер для Telegram на телефоне. Постоянный публичный адрес, например условный `https://studly.example`, ведёт на сервер в интернете. DNS связывает домен с сервером, а TLS-сертификат обеспечивает защищённое соединение HTTPS. `.example` здесь только пример; этот домен проекта не зарегистрирован.

Telegram Mini App открывает обычный веб-интерфейс по HTTPS внутри Telegram. Поэтому размещать нужно и интерфейс, и API; публикация одного JSON API не создаст работающего приложения.

Для существующей сессионной авторизации предполагается общий адрес интерфейса и API. Сервер маршрутизации принимает HTTPS-запросы: `/api/` и `/admin/` направляет в Django, остальные страницы — в Next.js; отдельно обслуживает служебные статические файлы Django. Это предложение для размещения, сейчас такой внешний сервер не настроен. Исходники и конфигурацию `apps/web` изменяет его разработчик.

## Что можно сделать с имеющимся токеном

Бот [@studly_service_bot](https://t.me/studly_service_bot) уже создан, токен подключён к локальному Backend. Ранее проверены его имя и описание. Повторно отправлять токен не требуется.

По Bot API можно установить текст и адрес кнопки меню методом `setChatMenuButton`, затем прочитать результат через `getChatMenuButton`. Для этого достаточно существующего токена и готового HTTPS-адреса интерфейса. В этом этапе меню не менялось: публичного работающего адреса ещё нет.

Токен Bot API не предоставляет доступ к покупке сервера, DNS, кабинету регистратора или личному аккаунту владельца в BotFather. Для сайта Telegram использует отдельные Client ID и Client Secret.

## Порядок постоянного размещения

1. Определить бюджет, регион и провайдера; владелец оформляет сервер и домен. Провайдер и тариф в этом этапе не выбирались, оплата не выполнялась.
2. Предоставить доступ к серверу через SSH и возможность настроить DNS. Для работ достаточно доступа к конкретному проекту; передавать пароль Telegram в чат не нужно.
3. Подготовить конфигурацию под выбранный сервер: запуск Django через сервер приложений, запуск согласованной версии Next.js, PostgreSQL в закрытой сети, секреты окружения, миграции, сбор служебной статики, перезапуск процессов и резервное копирование. Текущий `runserver` остаётся локальным инструментом разработки.
4. Привязать DNS к серверу и настроить выпуск и автоматическое обновление TLS-сертификата. Включить `DJANGO_DEBUG=false`, точные разрешённые хосты и доверенные origin; согласовать обработку HTTPS за прокси и проверить secure-cookie. Не публиковать локальный отладочный сервер как рабочее приложение.
5. Разработчику Frontend подключить авторизацию и API по [действующему контракту](API_CONTRACT.md). Его текущая версия ещё использует статические данные; наши изменения ограничены Backend.
6. Проверить публичные `/api/v1/health/`, `/api/v1/ready/`, каталог, cookie, CSRF и отсутствие утечки скрытых услуг. `ready` проверяет доступность БД; он не подтверждает готовность всех внешних сервисов или применение всех миграций.
7. Настроить кнопку меню бота на настоящий адрес интерфейса. При необходимости включить Main Mini App в BotFather, чтобы приложение открывалось также из профиля бота.
8. Владельцу открыть BotFather → выбрать бота → Login Widget: зарегистрировать origin сайта и точный callback, получить Client ID и Client Secret. Это действие требует сеанса владельца; Bot API его не заменяет.
9. Записать параметры в приватное окружение Backend, перезапустить и проверить вход настоящим аккаунтом: из Mini App и из браузера, затем выход и повторный вход. Проверить используемые клиенты Telegram, включая особенности cookie во встроенном браузере.

При общем домене адрес возврата будет:

```text
https://<ваш-домен>/api/v1/auth/telegram/callback/
```

В окружении Backend используются `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OIDC_CLIENT_ID`, `TELEGRAM_OIDC_CLIENT_SECRET`, `TELEGRAM_OIDC_REDIRECT_URI`. Секрет вводится непосредственно в приватное окружение. Значение Client ID сверяется с BotFather; текущий Bot ID не заменяет эту сверку. Значение redirect URI должно точно совпадать с зарегистрированным адресом.

Отдельный webhook для запуска Mini App и нынешней авторизации не требуется: Backend проверяет подписанные данные запуска и ответ OIDC. Обработка сообщений боту и уведомления — отдельная будущая функция.

## Кто выполняет действия

Настройку Backend, сервера, маршрутизации HTTPS и кнопки меню можно выполнить при наличии доступа. Владелец оформляет платные ресурсы и выполняет действия в BotFather, недоступные по токену. Подключением клиентского интерфейса занимается разработчик Frontend. Это внешние зависимости для настоящего входа; автоматические серверные тесты их не заменяют.

Официальные источники: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [кнопка меню Bot API](https://core.telegram.org/bots/api#setchatmenubutton), [Allowed URLs и Client Secret](https://core.telegram.org/bots/telegram-login#registering-your-allowed-urls), [проверки перед публикацией Django](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/).
