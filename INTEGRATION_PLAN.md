Дата: 15 октября 2026 года. Владелец разрешил следующий этап и интеграцию с Frontend, чтобы увидеть работающий результат локально.

## План

1. Создать каталог услуг в PostgreSQL: сумма, валюта, срок, описание, состав услуги и связь с пользователем-исполнителем. Публичное API пока разрешает только чтение, поиск и пагинацию.
2. Перенести четыре услуги и описания исполнителей из существующих детальных страниц в явно демонстрационные записи. Не переносить вымышленные рейтинги, статистику и дополнительные платные опции как реальные данные. Демонстрационные пользователи не получают выдуманные Telegram ID; для них разрешается пустой Telegram ID и отсутствует пароль. Подтверждённый вход Telegram продолжает требовать положительный Telegram ID.
3. Подключить главную, каталог/поиск, детальную услугу, профиль исполнителя и избранное к одному API. Избранные ID пока хранятся в браузере. Показать загрузку, ошибки с повторной попыткой, пустые результаты и отсутствие записи.
4. Подключить отображение текущего аккаунта, запрос CSRF и выход; показать понятное состояние отсутствующих настроек входа. Не добавлять обход входа или фиктивную Telegram-сессию. Заказы и чат не выдавать за работающие серверные функции.
5. Направить браузерные `/api/` через Next.js в Django, чтобы каталог и cookie работали с одного адреса. Доступен только локальный запуск; публикация и HTTPS остаются отдельным шагом.
6. Проверить API на отдельной PostgreSQL, проверить сборку/типы Frontend и ключевые сценарии в браузере. Запустить обе части и открыть приложение владельцу.

В этот этап не входят платежи, публикация услуг пользователями, жизненный цикл заказов, модерация и серверный чат. Соответствующие правила ещё не определены. Категории не назначаются услугам автоматически по названию.

- В прежней интеграции главная, поиск, услуга и публичный профиль использовали общий клиент API. Исторический файл `/Users/viktorkovarov/Downloads/Studly-main/apps/web/src/lib/api.ts` убран из рабочей версии и сохранён в указанной выше резервной копии. Избранные ID хранились отдельно в браузере; цены и описания загружались из PostgreSQL.
- [Next.js](apps/web/next.config.ts) сохраняет завершающий слеш адресов Django; устранён обнаруженный цикл перенаправлений. Браузерная проверка подтверждает CSRF и cookie через прокси.
- Серверные тесты того этапа: 44 успешных. Браузерные сценарии: 12 успешных в Chromium на экранах 1280×900 и 390×844; тот же набор также проверялся в установленном Yandex. Исторический файл `/Users/viktorkovarov/Downloads/Studly-main/apps/web/e2e/catalog.spec.ts` убран из рабочей версии и сохранён в указанной выше резервной копии; это не тесты текущего Frontend.
- Сборка и TypeScript проходят. Используется Webpack: Turbopack в данной среде падает при обработке CSS с ошибкой открытия локального порта. В новых и изменённых файлах интеграции ESLint проходит. Общий lint по-прежнему выявляет семь ошибок старых прототипов заказов/чата и предупреждения; правила линтера не отключались.

Полноценный вход Telegram не объявляется завершённым: нужны публичные адреса, OIDC Client Secret и проверки реальных клиентов. Заказы, чат, платежи, публикация и категории не реализовывались; соответствующие экраны помечены как находящиеся в разработке.
